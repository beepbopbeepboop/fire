  fix typed-pointer method dispatch.
- **MLIR-internal fields / libc bindings** (`gpu/*`, `_libc.mojo` — header

## Error Class Descriptions

Each distinct error class below links back to the AST bugs that cause it.

### SLIB-IMPLICIT-001 — Implicit declaration of function (majority of failures)
**~60 failures.** GCC warning-as-error: a function is called before it is declared. Root causes:
- **BUG-029** (BUGS-AST.md): Nested functions/closures that aren't in the pre-pass are silently dropped — the function body is never emitted, but call sites still reference the mangled name.
- **BUG-001**: `LambdaExpr` not in dispatch table — lambdas passed as sort comparators, map/filter callbacks, etc. are never emitted as functions.
- Name mangling mismatch: the caller and the callee use different mangled names (e.g., `cmp_fn` vs `MyStruct___lt__`).

**Fix path:** Fix BUG-029 first (on-the-fly closure lifting), then BUG-001 (lambda codegen). Together these will eliminate the majority of implicit-declaration failures.

---

### SLIB-ARITY-001 — Too many arguments to function
**~12 failures.** The generated call passes more arguments than the function declaration accepts. Root causes:
- `self` is being passed explicitly when the method is declared as a non-member (or vice versa).
- Default parameter values are counted as required call-site arguments.
- Variadic parameter packs (`*args`) are expanded incorrectly.

**Fix path:** Audit method call codegen — check whether `self` is being passed at the call site when the function was declared to receive it as a hidden first arg. Cross-reference with BUG-032 (variadic param detection).

---

### SLIB-CONV-001 — Non-trivial conversion in var_decl/function_decl/parm_decl
**~8 failures.** GCC GIMPLE type error: a variable, parameter, or function is declared with type A but initialized/called with type B and the implicit conversion is non-trivial. Root causes:
- Struct types returned by value vs. by pointer mismatches.
- Integer width mismatches (e.g., `int` vs `int64_t`).
- Related to BUG-011 (IntLiteral with string value).

---

### SLIB-SUB-001 — Subscripted value is neither array nor pointer
**~8 failures.** The codegen emits `x[i]` where `x` is a non-pointer type (e.g., a struct, an int, or a void). Root causes:
- SubscriptExpr on a generic/parametric type whose concrete type was not resolved — the struct itself is used rather than the internal pointer.
- SIMD indexing emits `simd_val[i]` but `simd_val` is typed as a struct, not an array.
- `UnsafePointer[T]` subscript: the struct wrapper is subscripted rather than the inner pointer field.

---

### SLIB-MEMBER-001 — 'X' has no member named 'y'
**~7 failures.** The codegen emits `struct.field` but the struct's C definition doesn't have that field. Root causes:
- Computed/alias fields (e.g., `SIMD.size`, `BitSet._words_size`) are not emitted as physical fields in the struct — they are `alias` or `@property` that should expand to expressions.
- Field name mapping from Mojo names to C names is inconsistent (underscore stripping, mangling).
- `MojoList.elem` and `MojoList.cap` are names that exist in Mojo struct definitions but are mapped to different names in the C runtime (`MojoList_data`, `MojoList_capacity`).

---

### SLIB-UNDECL-001 — Variable undeclared
**~5 failures.** A C variable is referenced before declaration. Root causes:
- For-loop iteration variable not declared before use (BUG-013 — tuple target in range loop).
- Counter variables inside comprehensions or with-statements dropped (BUG-030).
- Variables in comptime branches not emitted (BUG-003 — ComptimeVarStmt unreachable).

---

### SLIB-ASSIGN-001 — Assignment to 'int64_t' type mismatch
**~4 failures.** Generated code assigns a pointer or struct to an `int64_t` variable. Root causes:
- Expression type inference returns wrong C type for struct-valued expressions.
- Pointer arithmetic results typed as `int64_t` when they should be `T *`.

---

### SLIB-CALL-001 — Invalid conversion in gimple call
**~4 failures.** A function argument has wrong type at the GIMPLE level (after type-checking). Root causes:
- Passing a struct where a pointer is expected (or vice versa) in method calls.
- `owned` vs `borrowed` argument passing: owned arguments should be passed by value, borrowed by pointer, but the codegen may not distinguish.

---

### SLIB-NOTSTRUCT-001 — Request for member 'X' in something not a structure
**~4 failures.** The codegen emits `x.field` but `x` has a primitive type (int, pointer) at the C level. Root causes:
- A Mojo struct type was lowered to a primitive C type in some contexts (e.g., single-field structs are sometimes collapsed) but member access still uses dot notation.
- `UnsafePointer._mlir_value`, `Span.pointer`, etc. — these are MLIR-level fields that should not appear in C output but are being emitted.

---

### SLIB-CALL-002 — Invalid call to non-function before '('
**1 failure** (`python_object.mojo`). The codegen emits a call to something that is typed as a non-function — e.g., calling a struct or integer value as if it were a function. Root cause: indirect call through function pointer stored in a struct field not properly dereferenced. Related to BUG-027.

---

### SLIB-IDX-001 — Array subscript is not an integer
**1 failure** (`_amdgpu.mojo`). The index in `array[i]` is not an integer type (e.g., a struct or float). Root cause: SIMD/vector lane index not reduced to integer before subscript.

---

### SLIB-PTR-001 — Passing argument makes pointer from integer without cast
**~4 failures.** An integer value is passed where a pointer is expected (or vice versa). Root cause: type inference for `UnsafePointer`, `Pointer`, or `UInt` address expressions returns `int64_t` instead of the correct pointer type.

---

### SLIB-COND-001 — Type mismatch in cond_expr
**1 failure** (`math.mojo`). The two branches of a ternary/conditional expression have incompatible types. Root cause: the codegen emits both branches without unifying their types.

---

### SLIB-CONV-002 — Invalid types in conversion to integer
**1 failure** (`test_interval.mojo`). A non-integer is converted to integer using an unsupported cast path.

---

### SLIB-BINOP-001 — Invalid operands to binary & (bitwise AND)
**1 failure** (`test_set.mojo`). Left and right operands of `&` have incompatible types (`int *` and `int`). Root cause: pointer-typed expression used in bitwise AND where a value type is expected.

---

### SLIB-ADDR-001 — Expected pointer as argument of unary '&'
**1 failure** (`test_simd.mojo`). `&expr` applied to a non-lvalue (e.g., a temporary). Root cause: `address_of()` or `UnsafePointer(to=x)` called on a register-valued expression.

---

### SLIB-PARSE-001 — Parse error in emitted C (`expected '=', ','...`)
**1 failure** (`test_file.mojo`). The generated C itself has a syntax error. Root cause: a codegen path emits a token sequence that is not valid C (e.g., a Mojo keyword leaks into the C output, or a statement is emitted outside a function body).

---

### SLIB-MISC-001 — Error in function body (line unknown)
**4 failures** (`pathlib/path.mojo`, `runtime/tracing.mojo`, `tempfile/tempfile.mojo`, `utils/coord.mojo`). GCC reported "In function 'X':" as the first diagnostic — the actual error is on subsequent lines not captured by the first-error filter. These require deeper inspection.
