CONTROL

One controller (Claude Code) routes work items to opencode workers, one git worktree each; one integrator merges and gates. Last edited 2026-09-29.

1. The model

sweep / bugs/ ──► controller ──spawn──► worker (opencode, ../work-N, branch work/NAME)
                      ▲                       │  commits on its branch, prints CONTROL-STATUS
                      │ status / claims       ▼
                      └────────────── ../work-N/work.log
finished branches ──► integrator (../work-integ, branch integ) ──► make gate ONCE ──► master (ff)
                          │ conflict / red gate
                          └─► controller marks culprit superseded, spawns a fix worker from its branch
  • Workers never gate. No make gate|check|bootstrap, no compile_stdlib.py. They run the narrowest test that shows their change works.
  • The integrator gates once over everything finished, so the ~30 min / tens-of-GB cost is paid per round, not per change. Green → master fast-forwards. Red → master untouched.
  • Next round is master + whatever is still outstanding: one bad set never blocks the rest.
  • Everything a worker prints goes to ../work-N/work.log (stdout+stderr, append-only), so what it did and skipped can be reconstructed later. exitcode is written when it exits.
  • Scratch files live in ../work-N/.tmp/ (TMPDIR is pointed there). Workers cannot write to /tmp; reference inputs (e.g. the sweep output) are copied into .tmp/ with spawn --file.
  • Bugs a worker hits but does not fix are filed as bugs/<AREA>_<slug>.md on its branch and committed. A bug it fully fixes has its doc git rm'd in the same commit (repo convention).

2. Preventing two workers on one problem — claims

Every task is spawned with one or more --claim strings: module:os, bug:CODEGEN_foo, or a repo path. Two claims conflict if equal or one is a path-prefix of the other; spawn refuses a conflicting task until the holder is integrated, abandoned or superseded. Workers run control.py claims before starting and must report, not edit, anything another worker holds. Claim the problem, not the file: shared registry lines (e.g. HOST_MODELLED in formal/imports.py) are edited by several workers on purpose, minimally, and the integrator resolves trivial conflicts.

3. Worker protocol (what the worker is told)

Full text: tools/control_prompt.md. Summary: stay in your worktree; read CLAUDE.md; never path-scoped git checkout; commit on your branch, end with a clean tree; add a test with the change; no shortcuts. The last line printed must be exactly one of:

linemeaningcontroller action
CONTROL-STATUS: DONEcomplete, committed, cleanintegrator takes it
CONTROL-STATUS: PARTIALreal progress committed, rest in a bug docintegrator takes it; queue the remainder
CONTROL-STATUS: NEEDS-INFOmissing direction (preceded by QUESTION: lines)answer, then respawn from its branch
CONTROL-STATUS: BLOCKEDconcrete obstacleread log; reroute or file bug

4. Commands

python3 tools/control.py spawn NAME --claim KEY [--claim KEY] (--task TEXT | --task-file F) [--file SRC] [--base BRANCH]
python3 tools/control.py status [-v]       # state, worker verdict, commits, dirty files, last log line
python3 tools/control.py claims            # live claims
python3 tools/control.py log NAME [-n N]   # tail work.log
python3 tools/control.py mark NAME STATE   # integrated | abandoned | superseded | ...
python3 tools/control.py report            # regenerate the table below
python3 tools/integrate.py [--dry-run] [--only NAME ...]   # merge finished branches, gate once, land on master

Model: opencode/space-bunny-free (override with CONTROL_MODEL or --model); launched as opencode --model M run --auto --dir ../work-N …. Registry: <git-common-dir>/control/tasks.json (flock-guarded).

Gate timing (why workers never gate): one full make gate is ~30 min. 25–35 min = on track; 35–60 = slow, inspect the jobs; >60 = stuck, needs help. python3 tools/gatewatch.py reads the integrator's tree (../work-integ): elapsed time and verdict, live gate processes with RSS/CPU, tail of build/suite.log. python3 tools/control.py digest NAME gives a worker's verdict, commits, diffstat and REPORT block without reading its log.

  • The piece-fix rule: fix forward before you bisect (user, 19:5x). "A batch of 34 branches with five 20-line fixes can be done in 10 minutes. Compare this time to a single split." The comparison, for a batch of n≈18–34: one bisect step = probes of 3–8 min each × ~log₂(n) (≈5) to name one culprit, then a full gate on the good half (15–20 min), then a re-batch gate (15–20 min): 45–80 min per culprit, repeated for every culprit. Fix-forward = an agent on the merged tree repairs all the customary breakages at once (≈10 min for five small fixes) + one probe of just the failing jobs (3–8 min) + one gate (15–20 min): ≈30–40 min for ALL of them. So when a batch goes red the loop now: (1) snapshots the exact merged tree as batchfix-N; (2) starts a worker ON it whose acceptance test is the failing jobs (confirmed alone, so not load) and whose brief lists the usual and customary breakages — a conflict resolved wrongly or half-applied, a helper renamed by one branch and called by its old name from another, a missing registration/estate entry for a new test file, a stale expected-failure marker or hard-coded count, two fixes of one thing (consolidate), an index/doc conflict — with the rules: smallest edits, never revert or disable a branch's behaviour, never delete or skip a test, commit each fix naming the branch it repairs, and if a problem is over ~50 lines or the cause cannot be found, stop with BLOCKED naming the suspect branch; (3) waits up to 25 min (network deaths are restarted by unstick as …-rN and followed); (4) probes just the failing jobs on the worker's branch (right track / wrong track), then runs the full gate on batch+fixes: green lands everything; (5) up to two attempts, each starting from the previous attempt's branch with the new failing jobs; (6) only then bisect (halves, failing jobs as the probe) and hand the first bad branch to a fixer. The decision procedure is therefore: merge all → gate once → piece-fix → (only if that fails) bisect.
