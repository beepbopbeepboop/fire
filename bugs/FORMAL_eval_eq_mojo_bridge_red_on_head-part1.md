# FORMAL_eval_eq_mojo_bridge_red_on_head-part1: Hoist per-block qS_k chain simplifications into named per-block facts

## Goal

The block-theorem prefix (per-block `…_self{k}` theorems) re-derives the nested `qS_k`/`qT_k` record-update chains inline, so each `…_self{k}` theorem rewrites the whole chain and the section is quadratic in block length. For `bigbody` this makes the kernel hit the `-M 6144` ceiling long before the universal theorem is read. Hoist the shared `qS_k`-chain simplifications into **one named fact per block** (`bigbody_blk_N_qs_chain`), so every `…_self{k}` theorem cites that fact by name instead of re-deriving the full nested `qS`/`qT` chain inline. Right now each `qS_k` embeds `qS_{k-1}`, growing the state term with `k` and costing O(2^depth) declarations per block.

## Acceptance

After the change, for `bigbody`:
- The generated arm64 proof declares exactly one named per-block chain fact per block (e.g. `have bigbody_blk_0_qs_chain : … := by ...`).
- Every `…_self{k}` theorem in the block references that named fact by name (e.g. `have hself_5 : arm64_runs … := ⟨bigbody_blk_5_qs_chain, ?_⟩; exact cert`) rather than re-deriving the full nested `qS`/`qT` chain inline.
- The per-block section is no longer quadratic in block length; total declarations grow linearly with the number of blocks.

Verified by text assertions on the generated bytes — no Lean run required.

- Assert (c) no `…_self{k}` theorem re-derives the full chain inline (no `simp [qS...]` spanning the whole chain).

### Decision needed (controller / owner)

1. **What the one-fact-per-block means.** Option A (recommended): the per-block
   chain fact is the prefix already proven by `…_self{m-1}`, and `…_self{k}`
   cites `…_self{k-1}` plus only ITS OWN last-step facts (linear). Name it by
   an alias `theorem {S}_qs_chain := {S}_self{m-1}` only if the controller
   accepts an alias as the "one named fact". Option B: keep the literal
   `have bigbody_blk_N_qs_chain : ∀ k ≤ m, arm64_runs … = some (qS_k st)` built
   once, and have every `self_k` cite it. Option B is a bigger rewrite of the
   same induction and does not lower the cost any more than A does.
   Recommendation: A, with assertions (a)-(c) rewritten to test the linear
   property (no `hs`/`hpc` for index < k-1 inside `…_self{k}`), because the
   doc's (a)-(c) as written test names, not cost.
