## Decisions already made
- **Owner/lifetime of a computed string: libSystem `strdup`, the block is NEVER freed.** Reasons (evidence): a formal value is one 64-bit word and a string is a bare `char *` (so no `{ptr,len}` descriptor); there is no heap in the executable (`LENGTH_DEPENDENT_METHODS["join"]`), but libSystem is always linked and `malloc` is already a supported extern; a frame-owned buffer would need a compile-time size bound (blobs are sized by append-site count) which a returned/unknown-length string does not have; never freeing keeps wave-9 point 3 true ("every string value has static-or-program lifetime"), so `model.string_has_static_storage()` stays `True` (update its docstring: "program lifetime, not only static"), and a computed string can be returned, stored and passed anywhere a literal can with NO new escape rule. Cost recorded in the model: a computed string leaks for the life of the process (O(total bytes produced)).
- `strdup` is chosen over `malloc`+`memcpy`: one call, copies including the NUL, no length arithmetic to get wrong. Allocation failure returns NULL and the next load faults; that is accepted and recorded (no silent wrong answer).
- **NUL obligation (recorded in code, one place):** a string value cannot contain a NUL because the NUL ends it. The buffer methods only ever transform NUL-free input into NUL-free output (`upper`/`lower` map letters to letters), so the obligation holds. Any FUTURE producer that can emit byte 0 (`chr(0)`, `replace(x, "\0")`) must refuse. State this in `STRING_BUFFER_NUL_OBLIGATION` (below).
- **ASCII-only rule:** `upper`/`lower` are lowered ONLY when the image has no non-ASCII literal (`not M.non_ascii_strings()`); otherwise refuse with the existing wave-9 style text naming the non-ASCII case (call `M.codepoint_refusal(construct, spelled)`, `formal/model/strings.py:~345`, with construct `f"{dotted}()"` and spelled = the receiver text; BUT its text is about BYTES-vs-CHARACTERS `len`; invariant 2 says a refusal must be true of the file. So instead add `buffer_case_refusal(dotted)` next to it in `strings.py`: "{dotted}() is refused: this image holds a non-ASCII string literal ({examples}) and `toupper`/`tolower` only change ASCII letters, where CPython changes every cased character" using `_non_ascii_examples(non_ascii_strings())`). Reason: `toupper("é")` leaves the bytes, CPython changes them, and the result would be a plausible wrong string. This also keeps the invariant "the image's literals are exactly its possible string contents" true (ASCII in, ASCII out).
- Only `upper` and `lower` in this step (same loop, one libc function different). `swapcase/capitalize/title/casefold` stay refused (different per-position logic) with a reason updated by step 11c.
- The result kind is `STR_KIND` (same as `lstrip`), so `m = s.upper(); m.find("X")` keeps working.

## Do NOT
- Do not call `free`, and do not add a per-call-site reuse buffer: a second call would overwrite the first result still held by the caller (this is the bug a "static scratch" design has).
- Do not put the buffer in the caller's frame: it dies on return, which would force a new escape rule and kill `return s.upper()`.
- Do not hand-write a second `STRIP_CHARS`-style table; use libc `toupper`/`tolower` (the lstrip history: hand loops per backend were each wrong once).
- Do not lower `upper` on a non-ASCII image.
- Do not edit `lib/`.
