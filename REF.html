gimple_codegen.py — Analysis & Refactoring Plan

Date: 2026-08-21 · Target: split the monolith into files under 4,000 lines without behavior change.

1. Executive summary

gimple_codegen.py is a 42,612-line single module containing one dominant class, GimpleGen (lines 4147–42348, ~38,200 lines, 474 methods), plus ten support classes and the public compile_* entry points. Half the code lives in just 15 oversized methods; 40% of all lines are comments. The file implements two complete lowering backends — the -fgimple C emitter and a plain-C++ fallback (including C++20-coroutine generator/async units) — inside the same class, sharing mutable state through ~150 instance attributes and several module-level globals.

The plan below splits it into 15 focused modules (each well under 4k lines) behind a thin, signature-compatible gimple_codegen.py facade, using mixin composition so all existing call sites and tests keep working unchanged.

3. Bugs & correctness risks (ranked)

B1 compile_linked leaks cross-compile global dedup state

confirmedbug

compile_to_gimple (gimple_codegen.py:42475–42476) and compile_to_gimple_with_cpp (:42509–42510) both clear the module-global sets _emitted_unresolved_stub_syms / _emitted_type_name at entry, with an explicit comment explaining this prevents stale “already emitted” markers leaking between unrelated compiles in one process (build_stdlib_dylib.py / compile_stdlib.py compile many modules per process).

compile_linked (:42555–42612) does not clear them. Any stub-suppression state populated by an earlier inline-mode compile suppresses emission in every subsequent link-mode compile in the same process → potential missing declarations / silent drift. Fix: clear both sets at entry (or better, move the state onto the instance / a compilation-context object — see A2).

B2 Set used as a boolean flag

_emitted_type_name is a set whose only payload is .add(True) (:2172, :39731–39732, :41709) — a one-shot “already emitted” bool masquerading as a set alongside a real dedup set. Fragile and confusing; replace with a plain bool (it is private; only internal uses found).

B3 Five copies of the compile pipeline have already drifted

compile_to_gimple, compile_to_gimple_with_cpp, compile_to_gimple_linked/compile_linked, and compile_to_c each hand-roll tokenize → parse → rewrite → construct GimpleGen → seed guards → gen_module. The drift is not hypothetical: BUG-2026-032 exists precisely because link mode was missing the sys.path.insert pre-scan the inline modes had (:42590–42599). Consolidate into one internal driver with mode switches.

B4 Cross-instance side channels via shared mutable boxes

_link_needs_cxx_box: list = [False] (:5088) is threaded through nested GimpleGen instances so deeply-nested import compiles can signal “needs C++ at link time” to the root (:5947, :6020, :42601–42607). Works, but it is undebuggable implicit coupling. Replace with an explicit compilation-context object passed down deliberately.

B5 Module-level mutable globals ⇒ reentrancy hazards

_emitted_unresolved_stub_syms, _emitted_type_name (:2165–2172), _compile_cache (:42366) are process-global and mutated during compiles. Single-threaded use is currently safe only because entry points happen to clear them; any nested/parallel use breaks silently. Fold into per-compilation context (see §6).

B6 Two independently-maintained lowering backends

The _cpp_* C++ fallback reimplements statement/expression semantics already implemented by _lower_*/_gen_stmt_* (name mangling, coercions, truthiness, iteration). Every semantic fix must be applied twice; divergence bugs are structural, not accidental. Short term: document the shared-decision points and add parity assertions where cheap. Long term: extract shared semantic helpers consumed by both (see §6, M13/M14).

B7 Path-based special-casing baked into codegen

“Self-host detection is PATH-BASED only” (:34060–34074) plus hardcoded phantom field tables (Span/StringSlice fat-pointer seeding, :34042–34058) keyed to compiling this repo’s own files. Any external project with same-named structs relies on the gating working forever. Isolate these behind one clearly-marked compatibility-shim module/function so the policy is testable.

B8 27 broad except Exception: swallows

Silent fallbacks (e.g. :6261, :14895, :23570) can mask real codegen defects as “stub emitted”. Not individually wrong — the stopgap-fallback design is deliberate — but each should either narrow the exception or carry a machine-readable reason so regressions surface in the stdlib-build skip audit (CLAUDE.md gate #2).

B9 id()-keyed memo caches

The Phase 2/3 perf caches (:4865–4910) key on id(node). Safe today only because the AST outlives one compile; fragile under any future caching across compiles or AST rebuilding. Flag with assertions/comments; consider keying on a node-index assigned during rewrite.

4. Code cleanups (non-behavioral)

  • C1 — Comment diet: 16.9k comment lines, many 20-line essays attached to individual attributes (:4206–4332 et al.). Move rationale/design narrative into docstrings or doc/; leave one-line intent comments at sites. Est. −8–12k lines of noise.
  • C2 — Dead/one-off scaffolding: e.g. _emitted_type_name.add(True) flag-set (B2), TODO-comment constants block (:4131–4140) that exist only to centralize strings — fine, but adjacent near-duplicate constants (_COMMENT_RANGE_UNEXPECTED vs ..._UNEXPECTED2) should merge.
  • C3 — Nested-helper sprawl inside giant methods: gen_module alone defines many inner closures (_collect_global_stmts, _is_foreign_main, …) that are effectively private passes; hoisting them to methods/functions is prerequisite to decomposing it.
  • C4 — Duplication between gen_func and _gen_struct_method (overload suffixing, param ctypes, forward-decl sync) — consolidate once visible in separate modules.
  • C5 — The nine _gen_for_* loop variants share label/temp bookkeeping shapes; factor a common loop-emission skeleton with per-iterable hooks (after split; do not mix with moves).
  • C6 — resolve false alarm, documented: the apparent 2,260-line resolve is actually the nested closure inside _merge_struct_inheritance (:1808–1823+); no duplicate-method bug exists at class level (verified programmatically).

Milestone gate: make bootstrap

make bootstrap (verify + validate-all) is the strongest end-to-end validation available and must pass at each Wave-2 milestone (it is too expensive for per-step runs):

  • stage1: the Python compiler (fire.py --dump) compiles every .mojo file plus the core .py sources (fire.py, fire_compiler.py, myinterpreter.py, module_loader.py, …) into stage1/; gimple_codegen itself is exercised via fire.py's transitive closure.
  • stage2/stage3: the compiled compiler re-dumps the same set.
  • verify diffs .ci/.tok/.ast/.pyi across all three stages; validate-all re-checks per-file via bootstrap-validate.mojo.

This matters doubly for this refactor: gimple_codegen.py compiles itself, so any behavioral drift in its output immediately surfaces as stage mismatches instead of lurking. Note make preflight hard-requires a single-file gimple_codegen.py — the facade layout satisfies this; a package-directory layout would not.

Binding constraints discovered (apply to ALL future extraction)

  1. The self-host closure inlines each imported module's defs once per import edge: a def must have exactly one physical home across gimple_* files.
  2. Plain cross-module function imports dedupe correctly (load_module precedent); the problem is exclusively methods under inheritance.
  3. checked_run caches gate results keyed only on listed --extra files — always pass new leaf files as --extra or use --no-cache while iterating.
  4. Path-based selfhost gating: absolute vs relative entry filenames change emitted code; gates use absolute paths.

Mixin wiring — blocked, WIP on refactor/mixin-wiring-wip

The five Wave-1 mixins plus extracted core/exprs were wired and Python-green (250/76), but selfhost failed at link: the compiled closure resolves self.method() by the lexically-enclosing class prefix (_GenCallsMixin__emit) without walking declared base classes. All seven groups form one mutually-recursive strongly-connected component, so no file partition satisfies per-file static resolution.

Path forward

  1. Preferred — function extraction: convert lowering families to module-level functions taking gen as first parameter (self.x → gen.x mechanical rewrite), thin delegating methods left on GimpleGen; land one family at a time behind gates. Bypasses method symbol resolution entirely — imports already proven safe.
  2. Alternative — compiler fix: resolve inherited-method calls to the defining class's symbol. Unblocks true mixins but touches struct-inheritance semantics for user code; higher risk.
  3. Fallback — accept single-file GimpleGen body (~27k lines); keep only non-class extractions (already landed).
