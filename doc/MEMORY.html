Compiled-Path Memory Architecture — Allocation, Ownership, Stack Homing

Scope: the GIMPLE/C path (fire.py build, --jit, the self-hosted mojoc) — runtime/fire_runtime.c plus what mojo/backend_gimple/* emits. Written: 2026-09-28, from a leak hunt that started at mojo_cstr_or_int_str. Every number in §5 was measured (recipe in §8), not inferred. Companion docs: doc/OWNERSHIP_MODEL.md (the language-level ownership design, Phases 0–6) and ownership_destruct.py (the analysis that is actually implemented).

1. Summary

  • The reported leak was real and is fixed. mojo_cstr_or_int_str(v) returns v itself when it is a boxed string and otherwise a fresh malloc'd decimal (mojo_str_from_int). Every Int-keyed dict get/set/contains/pop, and every string comparison against an int-typed operand, leaked one small string per call. Measured on a 4M-iteration Dict[Int, Int] loop: 198 MB → 9.4 MB, output unchanged.
  • It was one instance of a general gap: heap strings have no owner. ~105 runtime functions return freshly allocated memory; the codegen emits a free for none of the string ones. Two classes of string are provably temporaries and are now released (§4); everything else is still immortal.
  • Containers built from a constructor are now freed, including inside loops. A container local is freed (and, for an empty literal, homed on the stack) when it is assigned once from a constructor and never escapes. Function-level candidates must also be definitely assigned at function exit; a container declared directly in a loop body is now owned by that body and freed at the end of each iteration and before every break/continue/return that leaves it (§3.B, §7.1). Measured: loop-local dict/list/set went from 540/232/456 B per iteration to flat. What still leaks is a container or string bound from a call result, a struct, and a string local (§5, §7.2–7.4).
  • Ownership now extends past constructors. A container bound from a slice, comprehension, + or call is owned when codegen proves the value fresh at the declaration; a user function that provably returns a fresh container hands ownership to its caller; a temporary consumed once (for iterable, extend source, + operand, len argument) is freed by its consumer; a struct instance is owned while nothing retains self. Each rule has a fail-closed default and a regression test that fails when the rule is disabled (§3.B/C, §5).
  • Speed: a short stack-homed list no longer calls malloc, the container registries are a dedicated pointer table, and the runtime is built at -O2 (it was -O0). On five micro-benchmarks we are at parity with or ahead of Rust on three, 2.6x behind on Int-keyed dicts and 1.7x behind on string building (§10). One loop each, one machine; not a general claim.
  • The rule that makes all of this tractable: data is homed on the stack when the solver can prove it does not outlive the frame; otherwise it has exactly one named owner, and the owner is the code that emits the free. Anything without an owner is a leak by definition (§3).

3. Who frees — the ownership classes

Every allocation in the compiled path belongs to exactly one class. The class decides both who frees and where the free is emitted. A value that fits none is a bug.

A. Stack-homed (no free needed for the struct, _destroy for its buffers)

The default target. A local container that the solver proves is owned solely by one frame gets its struct in that frame's storage (emit_infra.maybe_stack_alloc_owned_ctor: a decls entry MojoList _owned_storageN_x; + mojo_list_init(&...)). It cannot leak the struct and cannot dangle past the frame that owns it, because nothing else was allowed to hold it. Only the internal buffers (data, slots, key copies) remain on the heap and are released by mojo_*_destroy. Today this is restricted to an empty constructor; address-taking is legal only in non-__GIMPLE functions (struct methods and lifted loop bodies are __GIMPLE, so the optimisation cannot reach them — see the note in §6).

B. Owned heap containers (single owner, freed at every exit)

A Phase-3 candidate that is not eligible for stack homing. ownership_destruct.py admits a name only if it is assigned once from a constructor, never returned/moved/aliased/stored/captured, only passed to provably non-retaining callees, and definitely assigned at every function exit. The free is emitted at each return and at fall-through. Exception path: a longjmp skips those frees, so each candidate is also pushed on a cleanup stack (mojo_cleanup_push_*) that mojo_raise unwinds to the catching level's checkpoint; the inline free cancels its own entry.

Block-scoped owner (loop bodies). ownership_destruct.analyze_scoped_locals credits a name to the loop body that declares it when: it is a candidate by the rules above; its one assignment is a direct child statement of a for/while body without else:; and the name is mentioned nowhere outside that declaration and the rest of that body (so plain-Python source that reads a loop local after the loop is left alone). Straight-line order inside one block is the proof that every path to the end of the body, or to a break/continue/return after the declaration, executed it — no definite-assignment analysis is needed. Emission is in emit_infra's block-scope section: gen_loop_body (the single place every loop lowering routes its body through) opens and closes the scope; emit_loop_exit_frees handles break/continue; _emit_owned_local_frees adds the live scoped names at each return. An empty-literal declaration is homed on the stack and re-_init'd each iteration; the exception path is the same cleanup-thunk stack (push at the declaration, cancel at the free). Fail-closed: a name is freed only if gen_loop_body armed it, so a loop lowering not routed through it (the regex-scan helpers, the compile-time-unrolled loop) keeps today's leak and can never double-free; break/continue free only entries whose recorded loop depth equals the current len(gen.loop_stack), so a break in an unhooked inner loop cannot free an enclosing loop's locals; and the free function is recorded at the declaration (matching the pushed thunk), not re-derived at the exit.

Locals bound from a call result ("maybe fresh"). A slice, a comprehension, a + or any call may build a new container or may return one somebody else owns (x = h.get() returning self.items). The analysis credits such a name as a candidate, and codegen decides at the declaration (maybe_push_owned_local): the name keeps ownership only if the lowered value is a temp a fresh-returning action created and nothing has claimed. Otherwise the name is dropped from the candidates right there and nothing about it is ever freed. Fresh-returning actions are (a) the runtime functions in _FRESH_CONTAINER_RETURNS (each checked against its source: every return yields a container created in the same function), (b) container displays, and (c) calls to a module function ownership_destruct.analyze_returns_fresh proves returns a fresh container: a plain function whose every path returns a value, and whose returned value is a display or a local (also return l^) assigned once from a display, definitely assigned at every exit, and escaping only through that return.

Callee information comes from the callee's own body (_summarize_params), never from a read/mut keyword: this compiler lowers a copy as the same pointer, so a keyword is not a guarantee. Async, generator, decorated, overloaded, imported-name and recursive callees are refused, and depth is bounded.

Struct instances are owned like containers (freed with free, cleanup kind MOJO_CLEANUP_PTR) when the name is bound to a constructor call of a struct in the vetted table (_build_analysis_structs: uniquely defined, no base class, no __new__) and every use is a field access, a method call whose self the method provably does not retain, or a function whose parameter is not kept; __init__ must not retain self; a bound method taken as a value (g = p.total) captures self and is an escape. A struct-typed name is freed at an exit only if it also passed the declaration gate, never merely because it is a candidate. Bindings are pre-scanned so a use lexically before the binding (in a loop) is still judged as a struct use.

A list that owns its own string ELEMENTS. mojo_list_append_str stores the pointer it is given and never copies it, so mojo_list_free on a list built by a runtime function that allocated every element releases the container and leaves the strings behind: String("a b c").split(" ") was ~48 B/iteration. Two runtime functions qualify — mojo_str_split and mojo_str_splitlines, each read to append nothing it did not allocate — and for those the owner emits mojo_list_free_owned_strs (elements, then the list) with the matching mojo_cleanup_push_list_strs unwind thunk. mojo_str_rsplit is deliberately NOT in the set: it hands its result the very same pointers its own scratch list holds. The list owning its elements is not the same as the PROGRAM being able to name one — kept.append(parts[0]) stores a pointer the element free would dangle — so the free is gated on ownership_destruct.list_elements_owned, which asks the strictly narrower question "may any ELEMENT of this list be named at all?" and answers only for the binding itself, len/repr/str/print/bool/hash/id, a statement, a comparison operand, a condition and not. A subscript read, iteration, a comprehension, a copy, a slice, + and extend all keep the plain mojo_list_free and today's leak: the same trade §7 records for nested list literals. A missed free leaks a few bytes; a wrong one frees a string literal.

Closure locals. A capturing lambda's value and the malloc(sizeof env) its constructor allocated with it are ONE allocation unit, freed together by mojo_closure_free (a method value is the other thing a bound method can be, and gets mojo_bound_method_free, which frees only the wrapper — self belongs to only one of the two). Ownership comes from ownership_destruct.lambda_value_owned: after the binding, the only acceptable mention of the name is as the CALLEE of a call, and a mention inside a nested def/lambda is rejected outright (a capture into an environment that can outlive the scope). It is deliberately NOT routed through _is_free_eligible_function, which refuses any function containing a lambda: the rule that guards is about CONTAINERS, and inside a closure the receiver rules that make d[k]/d.x/d[a:b]/for x in d safe are not safe, so lifting that exclusion is separate work (§7). A lambda declared inside a loop is owned by the loop BODY on analyze_scoped_locals's terms, never by the function — it does not exist on the path to the fallthrough before the first iteration.

A callee that provably returns a fresh STRING hands it to the caller exactly as one returning a fresh container always has. analyze_returns_fresh accepts only a container display (or a local bound to one); _is_fresh_string_expr adds the three forms read off the lowering rather than inferred from a type — a + (mojo_str_cat always copies), an f-string, and a slice (mojo_cstr_slice) — and deliberately not str(s)/String(s) (the identity for a string), a bare string method call, or any other call, each of which can return its own argument.

String locals. A local bound to a provably fresh string is owned and freed with free (cleanup kind MOJO_CLEANUP_PTR). Freshness is earned, not assumed: _FRESH_STRING_RETURNS holds the 10 runtime functions (mojo_str_cat, mojo_str_from_int, mojo_char_to_str, mojo_cstr_slice/repeat/reverse, mojo_repr_str, mojo_hex/oct/bin) that a mechanical pass over all 92 char *-returning functions found to allocate on every return path; upper, lower, strip, replace, join, expandtabs, the padders and repr_float failed it (they return their own argument, or a static ""/"nan") and a free of either would crash. Strings needed three rules containers did not: (1) str is off the non-retaining builtin list (for a string it is the identity: x = str(s) lowers to x = s); (2) a method call on the string is allowed only where its result is consumed on the spot (ownership_destruct.receiver_results_consumed: a bare statement, a len/print/bool argument, a read-only operator operand, a condition), because many string methods return their receiver and t = s.strip() would alias it; (3) reads that only look at the value are not escapes for a non-struct name: the left operand of + * % == != < > <= >=, a right operand after a string literal, not s, an if/while/ternary condition. Never and/or (the result is an operand), never a right operand after an identifier (the left one may be a user type whose __add__ keeps it), never a struct. Both aliasing rules are mutation-tested: with either removed, the negative test's stored strings read as freed memory under MallocScribble and its comparisons fail.

C. Transient temporaries (owned by the expression that created them)

A heap value that one lowering creates, one runtime call consumes, and nothing else can name. The creator frees it immediately after the consumer. This is the class the leak belonged to; §4.

Container temporaries. A container built by an expression and consumed exactly once is freed by its consumer: the iterable of a for (freed when the loop statement ends, so break, else and an early return are all covered; registered at the outer loop depth so a break in the body never frees it), the source of extend, the operands of a list +, and the argument of len(...). Freshness is decided at the consuming site from the operand's node kind (a display, call, slice or + — never an identifier) plus membership in a set of values a fresh-producing action created and no consumer has claimed. Only pure copy-consumers free; a pure query such as the mojo_list_len behind a truthiness test does not, because the caller may reuse the value. The f-string hole: a use inside an f-string is invisible to the analysis (its {expr} is parsed at codegen), so an occurrence count treats any string containing { and the name as a use.

String temporaries. The same bargain, and it needed owned_free_fn_for rather than the container table: len(<fresh string>) reads the length and nothing else, so it frees the operand after the read (emitting the call first — freeing before it is a use-after-free, which is what the first version of that did). Every producer that puts a char * in the fresh set allocates it, so a free cannot hit a string literal: a literal is not the lowered value of a call.

D. Borrowed (never freed)

String literals (_slit_N pool), a boxed string that mojo_cstr_or_int_str returns unchanged, dict/set keys read back out, elements of a list of str. Freeing any of these is a crash, so the ownership predicate for class C must be able to tell C from D (§4.1).

E. Ownerless (leaks)

Everything else: a string bound to a local or field, a struct instance, a boxed mutable local, a nested def's environment (created and called without ever being bound to a local — 16 B/iter, §7), a bound method that escapes, the registries' entries for leaked containers, the element strings of a list whose elements can be named, a container returned from a call whose freshness cannot be proven. These are the gaps §7 orders.

4. Transient temporaries — the protocol that fixed the reported leak

4.1 Int dict keys and string comparisons

char *mojo_cstr_or_int_str(int64_t v);                 /* runtime */
void  mojo_cstr_or_int_release(int64_t orig, char *s); /* frees s iff s != (char *)orig */
  • Ownership is decidable at runtime from the pair (orig, s): the function returns orig unchanged for a boxed string (borrowed, class D) and a fresh decimal for an Int (owned, class C). release frees exactly the second case.
  • Codegen: _char_to_cstr(typ, val, transient=True) records key-temp → orig in gen._cstr_key_src. _emit_call emits the release immediately after the one call that takes the key, and consumes the entry, so a key can be released at most once. The table is reset per function (temp names such as _t12 repeat across functions; a stale entry would free something that never owned anything).
  • Opt-in contract (the caller promises both): exactly one runtime call consumes the key, and that call copies or merely reads it. Verified for every opted-in site: dict get/set/augmented-set/contains/pop/setdefault/del (the runtime strdups the key on insert) and mojo_cstr_cmp. Not opted in (keys stay unreleased, i.e. leak): the dict-subclass __missing__ path (the key is passed to user code that may keep it), the dict comprehension (it emits its set call as a raw string, not via _emit_call), and list.insert on a str list (the list stores the pointer).
  • Superseded for dict operations (§10.4): a dict get/set/in/pop/setdefault whose key is an untracked int64_t no longer builds this string at all; it passes the raw word to a _kw entry point. The conversion and release described here remain for string comparisons and as the fallback when a placeholder reaches a function with no _kw twin.
  • Failure mode: a transient key whose consuming call raises leaks one small string (the release is on the fall-through path only). Freeing a wrong pointer is not reachable: the entry only exists for a heap conversion this same site made.

4.2 Concatenation chains

mojo_str_cat always copies, so in a + b + c and in an f-string's running accumulator every intermediate is dead the moment the next cat returns. emit_infra._emit_str_cat(lv, rv, free_left, free_right) emits the cat, frees the operands the caller proved fresh, and registers its own result in gen._fresh_str_tmps so a parent cat can free it in turn. String + Int also frees its own mojo_str_from_int/mojo_char_to_str conversion temp. _is_fresh_operand requires both that the value is in the fresh set and that the operand's AST node is itself a + — so s = a + b; t = s + c (operand node is an identifier that merely aliases a fresh temp) is never freed out from under s. Measured on var c = k + "b" + "c" + "d": the two intermediates no longer leak; only the final string bound to c does (class E).

6. Design: stack first, one owner otherwise

  1. Stack-home by proof, not by default. The solver's question for every allocation is "does this value escape its frame?" Escape means returned, moved (^), stored in a wider-lifetime location, appended to an outer container, captured by a closure, or passed to a callee that may retain it. No escape → class A (frame storage). Escape → class B (one owner, one free site per exit) or class E, which must be an explicit, visible fallback, never an accident.
  2. Heap only for what the stack cannot hold. A stack container's struct is free; its growth buffers are the only heap it needs, and they are owned by the struct, so _destroy at the scope exit frees all of it. This is why class A cannot leak.
  3. Temporaries never reach the heap ownership question. A transient (class C) is created and consumed inside one lowering. Homing it on the stack would be better still — char buf[24] for a decimal key — but address-taking is illegal in __GIMPLE-tagged bodies (emit_infra Phase-6 note: verified with gcc -fgimple; struct methods and lifted loop bodies are __GIMPLE). The heap-plus-release protocol of §4 is the form that works in every function kind. If those bodies ever stop being __GIMPLE, class C becomes a stack buffer and release disappears. The runtime side is already shaped for it: orig vs s is the only ownership test.
  4. Ownership is expressed at one place per class, and the free is chosen for a VALUE, not a type. Class A/B: emit_infra's Phase-3/6 section. Class C: _emit_call's release hook and _emit_str_cat. owned_free_fn_for(gen, val, ctype) is the one function that answers "which free for THIS value", and the three cases that need it all look alike from the type: a list built by mojo_str_split owns its element strings, a fresh char * is a plain malloc block, and a MojoBoundMethod's self is the receiver's or the closure's depending on which of the two it is. A new allocation kind picks a class, records the property at the point where the value is still the temp its producing call returned, and adds its free through that one function; it does not get its own ad-hoc free.
  5. Exceptions. Class B survives longjmp via the cleanup stack. Class C does not (one small string leaks on the raise path). Extending the cleanup stack to a MOJO_CLEANUP_CSTR kind would close it if it ever matters.

7. Remaining gaps, and the decisions taken

Landed 2026-09-28 (details in §3–§4 and §10): transient Int keys and concat temporaries; block-scoped destruction; the solver widened (iterated locals, per-loop declarations, callee summaries from the callee's own body, stack-homed non-empty literals); temporary containers consumed by for/extend/+/len; call-result locals owned when provably fresh; user functions proven to return fresh containers; struct instances; small-buffer lists; a dedicated pointer table for the registries; the runtime built at -O2.

Landed 2026-09-30: the per-slot element-KINDS side table's home function and deletion (§2.1 — it was losing live entries, and a heterogeneous list read with no kinds hands a double's bit pattern to strlen); a list that owns its own string elements, with the element-escape rule that gates it; a callee proven to return a fresh string, and the len that consumes one; a capturing lambda's bound method freed together with the environment it was allocated with, and the bound-method registry entry discarded so that freeing one is safe at all (§3.B). The four bug docs those closed are deleted; what is left, most valuable first:

  1. Containers nested inside a literal ([[1, 2], [i]], 212 B/iter). The outer list is owned; its inner lists have no owner. Freeing them with the outer is only sound if no element read from the outer can escape (x = m[0]; return x would then return a freed list), which needs an analysis of element reads that does not exist. Left leaking on purpose.
  2. Strings whose elements or provenance the program can name (~48 B/iter, deliberately left). Locals bound to a provably fresh string are owned (§3.B), and since 2026-09-29 so are the results of upper/lower/strip/lstrip/rstrip/replace/join/expandtabs/padding: the runtime functions always return a copy (_str_fresh_copy; the price is a copy where Python returns the same object for an unchanged string), so they are on the fresh list, the receiver-result rule is relaxed for them, and a temporary receiver (s.lower().lstrip()) is freed after the call. Since 2026-09-30 a callee proven to return a fresh String hands it to its caller, and the strings inside a split() list are freed with the list. Still leaking: a split() result whose ELEMENTS the program can name (parts[0] stored somewhere, for p in parts, list(parts), parts[:], parts + other, extend) — list_elements_owned answers only for the binding itself, len/repr/print and a comparison. Widening it is the same missing analysis as item 1, below, and for the same reason.
  3. The two closure halves that are left (16 B/iter and per call). A nested def that is created and called without ever being bound to a local has nothing to hang a free on, and the box for a {mut}-captured local is what the closure's environment HOLDS, so its lifetime is the closure's, not the function's — freeing it at the function's return needs the reverse of the escape analysis that now exists ("no closure built here escapes it"), and a box reachable from a returned closure is a use-after-free. Measured 2026-09-30 with tools/mem_slope.py (§8): +32.17 B/iter for the {mut}-capture + nested-def + bound-method shape (4.62 MB at 100k, 13.83 MB at 400k) — one malloc(8) box, the env struct and mojo_bound_method_new per call, all class E. That figure was itself a reduction: analyze_returns_fresh used to refuse any function containing a nested def/lambda, and it now decides its veto against the actual capture set (FunctionDef.captures), which recovered 106 B/iter on a caller binding a closure-bearing callee's fresh container (138.50 → 32.17 B/iter on build/memprobes/callee_returns_fresh.mojo). Also open: lifting the exclusion of functions containing a nested def/lambda from container ownership analysis, whose receiver rules are not switched off inside a closure (so lambda k: d[k] would not disqualify d). Written up, with the measurements, in bugs/CODEGEN_closure_env_and_boxed_local_never_freed.md.
  4. Boxes (one 16-byte MojoBox per double-slot read of a heterogeneous list, cached per list and freed only as the cache array, never individually, and never unregistered from _reg_box). A boxed value is a value the program may still hold, so this needs the same element-escape analysis as item 2 — not attempted.
  5. Fixed 256-byte sprintf buffers in %-format: replace with a sized snprintf and release it as class C.
  6. Dict comprehension keys, __missing__ keys: route the comprehension's set call through _emit_call; __missing__ stays unreleased by contract.
  7. Speed still behind Rust: string building (1.7x); the string-keyed dict may have slipped to ~1.1x (§10.4). Int-keyed dicts are now within ~1.1x.
  8. Not yet done: stack-homing inside lifted loop bodies (not investigated), and Dict/Set string keys still strdup per key (an integer-keyed or integer-element small dict/set now allocates nothing when stack-homed).
  9. Int-keyed iteration is name-scoped: for k in d / .keys() / .items() return integer keys only when d is a local or parameter annotated Dict[Int, V] at every binding (_compute_int_keyed_dicts). A dict reached any other way (field, call result, unannotated) still yields string keys.

Considered and declined (measured): skipping the container registry for a stack-homed container the solver proves is never boxed. After the pointer-table rewrite the registry costs ~0.5 ns of a 5.8 ns list lifecycle (~8%), and skipping it means proving no int64_t ever holds the pointer, which an untyped callee parameter breaks; a misclassified pointer is a wrong-behaviour bug, not a leak. Not worth the risk for 8%.

Bugs found on the way, filed: (fixed since: an inferred var a = 0 was a 32-bit int and wrapped; it is now 64-bit), bugs/CODEGEN_set_annotated_empty_braces_lowered_as_dict.md (var s: Set[Int] = {} does not compile), and bugs/CODEGEN_list_element_read_defaults_to_str_across_a_call.md (2026-09-30: an unannotated List bound from a call result reads every element with mojo_list_get_str, so a float slot's bit pattern reaches strlen — a SIGSEGV, and the mirror of bugs/CODEGEN_list_of_string_read_as_int_when_filled_in_a_callee.md, which is a different root cause and is untouched by any of this work). Fixed and deleted 2026-10-01: a callee that returns a heterogeneous list is now marked, so the caller's read lowers as a BOXED one and the runtime answers per slot — and the box carries the slot's kind byte, so a char * slot is described as the string it is rather than as its own address decimal.

A test that was passing vacuously. test_ptr_registry.py compiles its harness with python3-config --cflags, which carries -DNDEBUG: every assert in it was compiled out, so the whole file reported PASS for any runtime at all (a deliberately broken delete still passed), and the -O3 in the same flags overrode the -O0/-O2 variants, making them the same build. Both are now dropped, and a one-line tripwire asserts they stay dropped. With the asserts live, three defects in the harness itself surfaced and were fixed: it strcmp'd mojo_cstr_or_int_str's return for values inside the boxed-string window, where the runtime correctly returns the word unchanged; it expected d->used == 4 after two pops of a seven-key dict; and its random model had two positions sharing key 0, which read as a phantom key at round 752 of 400,000. The general lesson: a test whose only verification is an assert needs a test that the assert is live.

8. How to verify a memory change

  1. tools/mem_slope.py <file.mojo> does all of this and is the instrument to reach for. It builds the program at both sizes — so the count is substituted into the source through a MEM_SLOPE_N placeholder, and a probe lacking one is REFUSED rather than measured vacuously (two runs of an identical binary prove nothing, which is the trap this replaces) — reads peak RSS from a fresh RUSAGE_CHILDREN per run, and reports B/iter. It fails on a build error and on output that differs between the two sizes, because a slope with moving output is a wrong-value bug wearing a leak's clothes. Probes for the classes in §5 are in build/memprobes/. Underneath it is the rule this section states: a flat pair is not leaking, a slope is B/iter, and a single size proves nothing.
  2. python3 fire.py build -o exe file.mojo reads its source to generate C; to look at the C for a case, call gimple_codegen.compile_to_gimple_cached(src, do_imports=True, filename=...) directly and search the function for mojo_*_new/free. The build's own .ci is deleted after linking.
  3. Delete the previous binary before each build. A failed build that leaves a stale executable makes a broken loop look like a passing "0 B/iter" row — this happened while writing this document.
  4. Any change under mojo/backend_gimple/*, gimple_codegen.py or the runtime owes the full make gate; for a behaviour-preserving change, byte-identical generated C is the stronger standard. A memory fix necessarily changes the C, so its evidence is the RSS slope plus unchanged program output.
  5. Keep a probe for every class in §5; an ownership regression is a slope that reappears.

10.1 The small buffer

MojoList carries MOJO_LIST_INLINE (4) slots inline. Invariants (runtime/fire_runtime.h): data is never NULL after init and cap >= MOJO_LIST_INLINE; data == inl iff the elements are still inline, and only _list_grow (copy out, never realloc) and mojo_list_destroy (never free) distinguish the two; a list must not be copied or moved by value while inline. Dict and set slot arrays could get the same treatment, but a dict/set of strings still strdups every key, so "no malloc" is not reachable for those without storing short keys inline (a larger change: keys are handed out as borrowed pointers).

10.2 The registries (_PtrReg)

The runtime tells a boxed int64_t that is a list from an int or a string by looking its address up in a registry, populated on every container init and cleared on every destroy. They were MojoSets: 32-byte slots, a % per probe, and a re-hash of the whole cluster on every erase. sample on the compiled loop put mojo_list_init+mojo_list_destroy, almost all of it registry probing, at well over half of the runtime. They are now _PtrReg: a set of non-zero addresses with power-of-two masking, 8-byte slots, a one-multiply hash and backward-shift deletion (no tombstones, so the LIFO add/remove of one address a stack-homed container produces never degrades the table). test_ptr_registry.py checks it against a reference model (1.5M random operations, forced collisions, 2M cycles on one address) at -O0, -O2 and under AddressSanitizer. The registry is still not free (~2 ns per container in the isolated runtime loop) and could be skipped for a stack-homed container the solver proves is never boxed; that needs an audit of every place a container pointer becomes an int64_t and is not done.

10.3 The runtime's optimisation level

build_stdlib_dylib.runtime_units added an optimisation flag only when a caller passed one, and the stdlib dylib build passes none, so the hand-written runtime — every container operation, the registries, the cleanup stack — ran at gcc's implicit -O0 in every compiled program (its own static inline hash helper was not even inlined). It now defaults to -O2 for the C/C++ units (an explicit flag still wins). The generated stdlib modules stay at -O0 for compile time. mojoc has always built the runtime at -O2, so this is a level it was already exercised at.

Same method as above (user CPU time, our ~0.017 s startup subtracted, best of 3, checksums verified equal to the Rust program's). Rust: HashMap/HashSet/Box/format! with black_box on the inputs so nothing is optimised away.

What moved them, in order. (1) A hand-rolled decimal formatter instead of snprintf (half of an Int-keyed access was vfprintf), a block pool for the transient key string, masked probing instead of a modulo per probe, and a dict resize that moves each key pointer instead of strduping and freeing every key: 2.6x behind Rust. (2) Integer dict slots: the last two thirds of the remaining gap was formatting the key to text, hashing the text and strcmping it on every access, so an integer key is now stored as an integer.

How integer slots work. A slot has keykind == 2 and an ikey field; that integer is what is hashed (a murmur finalizer) and compared. The slot also keeps the key's decimal string in key, exactly the string it always held, so everything that reads a key as text (iteration, repr, copy, update, pop's rebuild, %-format) is unchanged. Normalization: any key that is a canonical decimal integer ("5", "-12"; never "05", "+5", "-0", or a value that overflows int64_t) is stored as an integer slot whether it arrived as the integer 5 or the string "5", so the two remain ONE key, as they always were here. Strings that only look numeric stay separate, and so do bytes keys. Codegen changes only the dict operations whose key is an untracked int64_t: _char_to_cstr(word_ok=True) returns a placeholder and _emit_call swaps the call for its mojo_dict_*_kw twin, passing the raw word. The twin makes the same "boxed string or integer?" decision mojo_cstr_or_int_str made (mojo_boxed_is_str), so which words count as strings did not change. If a placeholder ever reaches a function with no twin, that function gets the string built the old way and released after the call. String comparisons keep that path. Pinned by: a reference-model test of the runtime layer (400,000 operations, negatives, extremes, canonical-integer detection, int/string equivalence in both directions, numeric-looking strings and bytes keys staying separate; gcc -O0/-O2 and AddressSanitizer), a C-shape test that the emitted code contains the _kw calls and no string conversion, and a program checked against CPython through every operation.

What it cost. The slot grew from 40 to 48 bytes (the ikey field), and the string-keyed dict measures ~1.1x Rust where it measured parity before. The machine was ~15% slower on the later run (Rust's own time moved by the same amount), so part of that is noise; part may be the wider slot. Not separated.

Follow-up fix: iterating an Int-keyed dict used to hand back the keys as strings (for k in d: total += k added string pointers). Loops over an annotated Dict[Int, V] name now read integer keys (mojo_dict_iter_key_int, mojo_dict_items_int); see §7. String building still allocates a result per concatenation and does not free the bound result (§7.2). A first version of the set benchmark failed to build: var s: Set[Int] = {} is refused (filed, §7).
