Compiled-Path Memory Architecture — Allocation, Ownership, Stack Homing

Scope: the GIMPLE/C path (fire.py build, --jit, the self-hosted mojoc) — runtime/fire_runtime.c plus what mojo/backend_gimple/* emits. Written: 2026-09-28, from a leak hunt that started at mojo_cstr_or_int_str. Every number in §5 was measured (recipe in §8), not inferred. Companion docs: doc/OWNERSHIP_MODEL.md (the language-level ownership design, Phases 0–6) and ownership_destruct.py (the analysis that is actually implemented).

1. Summary

  • The reported leak was real and is fixed. mojo_cstr_or_int_str(v) returns v itself when it is a boxed string and otherwise a fresh malloc'd decimal (mojo_str_from_int). Every Int-keyed dict get/set/contains/pop, and every string comparison against an int-typed operand, leaked one small string per call. Measured on a 4M-iteration Dict[Int, Int] loop: 198 MB → 9.4 MB, output unchanged.
  • It was one instance of a general gap: heap strings have no owner. ~105 runtime functions return freshly allocated memory; the codegen emits a free for none of the string ones. Two classes of string are provably temporaries and are now released (§4); everything else is still immortal.
  • Containers built from a constructor are now freed, including inside loops. A container local is freed (and, for an empty literal, homed on the stack) when it is assigned once from a constructor and never escapes. Function-level candidates must also be definitely assigned at function exit; a container declared directly in a loop body is now owned by that body and freed at the end of each iteration and before every break/continue/return that leaves it (§3.B, §7.1). Measured: loop-local dict/list/set went from 540/232/456 B per iteration to flat. What still leaks is a container or string bound from a call result, a struct, and a string local (§5, §7.2–7.4).
  • The rule that makes all of this tractable: data is homed on the stack when the solver can prove it does not outlive the frame; otherwise it has exactly one named owner, and the owner is the code that emits the free. Anything without an owner is a leak by definition (§3).

3. Who frees — the ownership classes

Every allocation in the compiled path belongs to exactly one class. The class decides both who frees and where the free is emitted. A value that fits none is a bug.

A. Stack-homed (no free needed for the struct, _destroy for its buffers)

The default target. A local container that the solver proves is owned solely by one frame gets its struct in that frame's storage (emit_infra.maybe_stack_alloc_owned_ctor: a decls entry MojoList _owned_storageN_x; + mojo_list_init(&...)). It cannot leak the struct and cannot dangle past the frame that owns it, because nothing else was allowed to hold it. Only the internal buffers (data, slots, key copies) remain on the heap and are released by mojo_*_destroy. Today this is restricted to an empty constructor; address-taking is legal only in non-__GIMPLE functions (struct methods and lifted loop bodies are __GIMPLE, so the optimisation cannot reach them — see the note in §6).

B. Owned heap containers (single owner, freed at every exit)

A Phase-3 candidate that is not eligible for stack homing. ownership_destruct.py admits a name only if it is assigned once from a constructor, never returned/moved/aliased/stored/captured, only passed to provably non-retaining callees, and definitely assigned at every function exit. The free is emitted at each return and at fall-through. Exception path: a longjmp skips those frees, so each candidate is also pushed on a cleanup stack (mojo_cleanup_push_*) that mojo_raise unwinds to the catching level's checkpoint; the inline free cancels its own entry.

Block-scoped owner (loop bodies). ownership_destruct.analyze_scoped_locals credits a name to the loop body that declares it when: it is a candidate by the rules above; its one assignment is a direct child statement of a for/while body without else:; and the name is mentioned nowhere outside that declaration and the rest of that body (so plain-Python source that reads a loop local after the loop is left alone). Straight-line order inside one block is the proof that every path to the end of the body, or to a break/continue/return after the declaration, executed it — no definite-assignment analysis is needed. Emission is in emit_infra's block-scope section: gen_loop_body (the single place every loop lowering routes its body through) opens and closes the scope; emit_loop_exit_frees handles break/continue; _emit_owned_local_frees adds the live scoped names at each return. An empty-literal declaration is homed on the stack and re-_init'd each iteration; the exception path is the same cleanup-thunk stack (push at the declaration, cancel at the free). Fail-closed: a name is freed only if gen_loop_body armed it, so a loop lowering not routed through it (the regex-scan helpers, the compile-time-unrolled loop) keeps today's leak and can never double-free; break/continue free only entries whose recorded loop depth equals the current len(gen.loop_stack), so a break in an unhooked inner loop cannot free an enclosing loop's locals; and the free function is recorded at the declaration (matching the pushed thunk), not re-derived at the exit.

C. Transient temporaries (owned by the expression that created them)

A heap value that one lowering creates, one runtime call consumes, and nothing else can name. The creator frees it immediately after the consumer. This is the class the leak belonged to; §4.

D. Borrowed (never freed)

String literals (_slit_N pool), a boxed string that mojo_cstr_or_int_str returns unchanged, dict/set keys read back out, elements of a list of str. Freeing any of these is a crash, so the ownership predicate for class C must be able to tell C from D (§4.1).

E. Ownerless (leaks)

Everything else: a string bound to a local or field, a struct instance, a closure env, a boxed mutable local, a bound method, the registries' entries for leaked containers, a container declared in a loop body, a container returned from a call and bound by the caller. These are the gaps §7 orders.

4. Transient temporaries — the protocol that fixed the reported leak

4.1 Int dict keys and string comparisons

char *mojo_cstr_or_int_str(int64_t v);                 /* runtime */
void  mojo_cstr_or_int_release(int64_t orig, char *s); /* frees s iff s != (char *)orig */
  • Ownership is decidable at runtime from the pair (orig, s): the function returns orig unchanged for a boxed string (borrowed, class D) and a fresh decimal for an Int (owned, class C). release frees exactly the second case.
  • Codegen: _char_to_cstr(typ, val, transient=True) records key-temp → orig in gen._cstr_key_src. _emit_call emits the release immediately after the one call that takes the key, and consumes the entry, so a key can be released at most once. The table is reset per function (temp names such as _t12 repeat across functions; a stale entry would free something that never owned anything).
  • Opt-in contract (the caller promises both): exactly one runtime call consumes the key, and that call copies or merely reads it. Verified for every opted-in site: dict get/set/augmented-set/contains/pop/setdefault/del (the runtime strdups the key on insert) and mojo_cstr_cmp. Not opted in (keys stay unreleased, i.e. leak): the dict-subclass __missing__ path (the key is passed to user code that may keep it), the dict comprehension (it emits its set call as a raw string, not via _emit_call), and list.insert on a str list (the list stores the pointer).
  • Failure mode: a transient key whose consuming call raises leaks one small string (the release is on the fall-through path only). Freeing a wrong pointer is not reachable: the entry only exists for a heap conversion this same site made.

4.2 Concatenation chains

mojo_str_cat always copies, so in a + b + c and in an f-string's running accumulator every intermediate is dead the moment the next cat returns. emit_infra._emit_str_cat(lv, rv, free_left, free_right) emits the cat, frees the operands the caller proved fresh, and registers its own result in gen._fresh_str_tmps so a parent cat can free it in turn. String + Int also frees its own mojo_str_from_int/mojo_char_to_str conversion temp. _is_fresh_operand requires both that the value is in the fresh set and that the operand's AST node is itself a + — so s = a + b; t = s + c (operand node is an identifier that merely aliases a fresh temp) is never freed out from under s. Measured on var c = k + "b" + "c" + "d": the two intermediates no longer leak; only the final string bound to c does (class E).

6. Design: stack first, one owner otherwise

  1. Stack-home by proof, not by default. The solver's question for every allocation is "does this value escape its frame?" Escape means returned, moved (^), stored in a wider-lifetime location, appended to an outer container, captured by a closure, or passed to a callee that may retain it. No escape → class A (frame storage). Escape → class B (one owner, one free site per exit) or class E, which must be an explicit, visible fallback, never an accident.
  2. Heap only for what the stack cannot hold. A stack container's struct is free; its growth buffers are the only heap it needs, and they are owned by the struct, so _destroy at the scope exit frees all of it. This is why class A cannot leak.
  3. Temporaries never reach the heap ownership question. A transient (class C) is created and consumed inside one lowering. Homing it on the stack would be better still — char buf[24] for a decimal key — but address-taking is illegal in __GIMPLE-tagged bodies (emit_infra Phase-6 note: verified with gcc -fgimple; struct methods and lifted loop bodies are __GIMPLE). The heap-plus-release protocol of §4 is the form that works in every function kind. If those bodies ever stop being __GIMPLE, class C becomes a stack buffer and release disappears. The runtime side is already shaped for it: orig vs s is the only ownership test.
  4. Ownership is expressed at one place per class. Class A/B: emit_infra's Phase-3/6 section. Class C: _emit_call's release hook and _emit_str_cat. A new allocation kind must pick a class and add its free at that class's single emission point; it does not get its own ad-hoc free.
  5. Exceptions. Class B survives longjmp via the cleanup stack. Class C does not (one small string leaks on the raise path). Extending the cleanup stack to a MOJO_CLEANUP_CSTR kind would close it if it ever matters.

7. Remaining gaps, in the order they should be closed

  1. Block-scoped container destruction — LANDED 2026-09-28. See §3.B for the design and §5 for the measurement. Known limits, each a solver-widening item below: a local that is iterated (for x in l:) is disqualified because the analysis treats any bare identifier outside its safe patterns as an escape; a name declared in two sibling loops (assigned twice per function) is not credited; a declaration that is not a direct child of the body (inside an if) is not credited; a loop with else: is skipped; and the analysis is called with empty callee tables, so passing the local to any user function disqualifies it.
  2. Returned containers. x = f() where f returns a fresh container: the caller becomes the owner. Needs the callee's "returns a fresh, unshared container" fact (the ownership doc's Phase 4 calling convention: owned = move) and then the same class-B free at the caller.
  3. Strings bound to locals. The largest population by count. A string local needs an owner, so needs the same escape analysis as containers plus a decision on the borrowed class (list-of-str elements, dict values, literals). Recommended first cut: free only a string local that is assigned from a string-returning runtime call, never escapes, and whose every use is a read.
  4. Struct instances, closure envs, boxed mutable locals. _alloc_<S> can become a stack S for a non-escaping local in a non-__GIMPLE function (same proof as class A). Boxed mutable locals are allocated once per call in the prologue; they can be frame locals whenever no closure that captures them outlives the frame.
  5. Bound-method registry. Either drop the registry (tag bound methods in-band) or discard on free; today a stale address can later be misidentified.
  6. Fixed 256-byte sprintf buffers. Replace _sprintf_one's malloc(256) + sprintf with a sized snprintf and release it as class C.
  7. Beef up the solver to stack-home as much as possible (queued 2026-09-28; start once loop-scoped destruction, item 1, is checked in). Every item above is limited by what the escape solver can prove. Widen it: non-empty container literals, non-escaping struct instances, closure envs and boxed mutable locals; real callee tables (the analysis runs with {}, {} today, so any user-function argument disqualifies a container); the missing safe patterns (for x in local:; a name assigned once per scope, so tmp = [] reused across sibling loops qualifies); stack buffers for non-escaping strings and transient decimals; and a GIMPLE-legal way to home storage in __GIMPLE bodies. Tracked in doc/OWNERSHIP_MODEL.md's TODO list. Success is the §5 table trending to all-flat.
  8. Dict comprehension keys, __missing__ keys. Route the comprehension's set call through _emit_call to opt in; __missing__ stays unreleased by contract.

8. How to verify a memory change

  1. Write the loop at two sizes (e.g. 100k and 400k) and compare /usr/bin/time -l ./exe "maximum resident set size". A flat pair is not leaking; a slope is B/iter. A single size proves nothing.
  2. python3 fire.py build -o exe file.mojo reads its source to generate C; to look at the C for a case, call gimple_codegen.compile_to_gimple_cached(src, do_imports=True, filename=...) directly and search the function for mojo_*_new/free. The build's own .ci is deleted after linking.
  3. Delete the previous binary before each build. A failed build that leaves a stale executable makes a broken loop look like a passing "0 B/iter" row — this happened while writing this document.
  4. Any change under mojo/backend_gimple/*, gimple_codegen.py or the runtime owes the full make gate; for a behaviour-preserving change, byte-identical generated C is the stronger standard. A memory fix necessarily changes the C, so its evidence is the RSS slope plus unchanged program output.
  5. Keep a probe for every class in §5; an ownership regression is a slope that reappears.
