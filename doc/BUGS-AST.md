# BUGS-AST.md — AST/Codegen Bug Audit

Generated by auditing `mojo_compiler.py` (AST + parser), `ast_nodes.py`, and `gimple_codegen.py`.

Severity scale: **critical** > **high** > **medium** > **low**
Categories: `missing_handler`, `attribute_mismatch`, `logic_error`, `stub`, `incomplete`

## Status updates (verified against current source)

- **FIXED:** BUG-001 (LambdaExpr dispatched), BUG-003 (ComptimeVarStmt wired),
  BUG-005 (f-string uses `._parse_expr(0)`), BUG-006 (elifs iterated),
  BUG-011 (`IntLiteral(value=0)` integer).
- **NEW (fixed):** Boolean `not` precedence. `not` was parsed as a tight unary
  prefix in `_parse_unary`, so `not x in y` parsed as `(not x) in y`. It is now a
  low-precedence prefix handled in `_parse_expr` (looser than comparison/`in`,
  tighter than `and`), matching Python. Fixed `test_inline_array.mojo`.
- **STILL OUTSTANDING:** BUG-002 (TstringLiteral), BUG-013 (for-range tuple
  target), BUG-024 (finally on normal path), BUG-029 (on-the-fly closure lift).

## Critical

### BUG-001 — LambdaExpr not in dispatch table
- **Severity:** critical
- **Category:** missing_handler
- **Node:** `LambdaExpr`
- **Location:** `gimple_codegen.py` — `_EXPR_DISPATCH`
- **Description:** `LambdaExpr` is produced by the parser (`mojo_compiler.py`) but absent from `_EXPR_DISPATCH`. Any lambda expression hits the fallthrough path in `lower_expr()` which emits `/* TODO: unknown expr LambdaExpr */` and returns a dummy zero int.
- **Fix:** Add `'LambdaExpr': '_lower_LambdaExpr'` to `_EXPR_DISPATCH` and implement the handler (closure-lift the lambda into a named function).

### BUG-002 — TstringLiteral not in dispatch table
- **Severity:** critical
- **Category:** missing_handler
- **Node:** `TstringLiteral`
- **Location:** `gimple_codegen.py` — `_EXPR_DISPATCH`
- **Description:** `TstringLiteral` is produced by the parser but absent from `_EXPR_DISPATCH`. Any t-string expression hits the fallthrough and emits `/* TODO: unknown expr TstringLiteral */`.
- **Fix:** Add `'TstringLiteral': '_lower_TstringLiteral'` to `_EXPR_DISPATCH` and implement expansion of format parts into concatenation calls.

### BUG-003 — ComptimeVarStmt not in stmt dispatch table
- **Severity:** critical (method exists but is unreachable)
- **Category:** missing_handler
- **Node:** `ComptimeVarStmt`
- **Location:** `gimple_codegen.py` — `_STMT_DISPATCH`
- **Description:** Handler `_gen_stmt_ComptimeVarStmt` exists in `gimple_codegen.py` but is NOT wired into `_STMT_DISPATCH`. `gen_stmt()` dispatches via `_STMT_DISPATCH`, so the handler is unreachable. Any `comptime VAR = expr` statement emits `/* TODO: ComptimeVarStmt */`.
- **Fix:** Add `'ComptimeVarStmt': '_gen_stmt_ComptimeVarStmt'` to `_STMT_DISPATCH`.

### BUG-004 — GlobalStmt missing everywhere
- **Severity:** high
- **Category:** missing_handler
- **Node:** `GlobalStmt`
- **Location:** `gimple_codegen.py` — `_STMT_DISPATCH` and `gen_module` top-level dispatch
- **Description:** `GlobalStmt` is produced by the parser but has no entry in `_STMT_DISPATCH` and no handler method. Any `global x, y` statement emits `/* TODO: GlobalStmt */`. Also not handled in `gen_module`'s top-level dispatch.
- **Fix:** Add handler and wire into both dispatch tables; mark variables as module-level (no C emission needed if globals are already tracked).

### BUG-005 — F-string re-parsing calls wrong method
- **Severity:** critical
- **Category:** logic_error
- **Location:** `gimple_codegen.py` — `_lower_StringLiteral` (~line 3780)
- **Description:** `_lower_StringLiteral` calls `_P(_tok(text)).parse_expr()` to re-parse f-string embedded expressions, but the Parser only defines `_parse_expr(min_prec: int)` — a private method with a required argument. The call raises `AttributeError` at runtime for any f-string with an embedded expression. The bare `except Exception: continue` silently swallows the crash, dropping expression parts from the output.
- **Fix:** Change `.parse_expr()` to `._parse_expr(0)`.

## High

### BUG-006 — ComptimeIfStmt drops all `elif` branches
- **Severity:** high
- **Category:** incomplete
- **Node:** `ComptimeIfStmt`
- **Location:** `gimple_codegen.py` — `_gen_stmt_ComptimeIfStmt`
- **Description:** Handler processes `node.condition`, `node.then_body`, and `node.else_body` but never iterates `node.elifs`. All `comptime elif` branches are silently dropped.
- **Fix:** After the then_body block, iterate `node.elifs`: for each `(elif_cond, elif_body)`, evaluate condition and process body.

### BUG-007 — RaiseStmt ignores exception object
- **Severity:** medium
- **Category:** incomplete
- **Node:** `RaiseStmt`
- **Location:** `gimple_codegen.py` — `_gen_stmt_RaiseStmt`
- **Description:** `raise` always emits `mojo_raise()` regardless of `node.value`. The exception object (e.g., `raise ValueError("bad")`) is completely ignored — not evaluated for side effects, not passed to the runtime.
- **Fix:** Evaluate `node.value` if present, pass result to a `mojo_raise_with_obj()` runtime function.

### BUG-008 — Top-level multi/comptime stmts fall to TODO
- **Severity:** medium
- **Category:** missing_handler
- **Location:** `gimple_codegen.py` — `gen_module` top-level dispatch
- **Description:** At the top level of `gen_module`, `VarDecl`, `MultiAssignStmt`, `ComptimeVarStmt`, `ComptimeIfStmt`, and `ComptimeForStmt` fall into the else branch that emits `/* TODO: top-level <NodeType> */`. These are valid top-level constructs.
- **Fix:** Add `MultiAssignStmt`, `ComptimeVarStmt`, `ComptimeIfStmt`, `ComptimeForStmt` to `toplevel_stmts` or handle specially in `gen_module`.

### BUG-011 — IntLiteral constructed with string value
- **Severity:** medium
- **Category:** logic_error
- **Node:** `IntLiteral`
- **Location:** `mojo_compiler.py` lines 1724, 1749, 1779
- **Description:** `IntLiteral(value="0")` is used three times. The dataclass defines `value: int`, so this is a type violation. Code in `gimple_codegen.py` that does arithmetic with `node.value` (e.g., `step_expr.value < 0`) will fail or produce wrong output (`"0" < 0` raises `TypeError` in Python 3).
- **Fix:** Change to `IntLiteral(value=0)` (integer, not string) at all three call sites.

### BUG-012 — Duplicate target string in for-loop parser
- **Severity:** high
- **Category:** logic_error
- **Location:** `mojo_compiler.py` ~line 1187
- **Description:** The tuple string construction `target = '(' + ', '.join(names) + ')'` appears on two consecutive lines. The second assignment is redundant and signals a copy-paste error.
- **Fix:** Remove the duplicate line.

### BUG-013 — For-range doesn't validate target is an identifier
- **Severity:** high
- **Category:** logic_error
- **Location:** `gimple_codegen.py` — `_gen_for_range`
- **Description:** `_gen_for_range` does `var = node.target` then `self._declare_var(var, 'int64_t')` without checking that `var` is a valid C identifier. For `for (a, b) in range(n):`, the codegen will declare invalid C identifier `(a, b)`. The `_gen_for_iter` path handles this correctly but `_gen_for_range` does not.
- **Fix:** In `_gen_for_range`, check if `var` starts with `'('` and either reject or fall through to `_gen_for_iter`.

### BUG-017 — AssignStmt: ast_nodes.py vs mojo_compiler.py field name mismatch
- **Severity:** high
- **Category:** attribute_mismatch
- **Location:** `AssignStmt` definition
- **Description:** `ast_nodes.py` defines `AssignStmt.targets: list` (plural), but `mojo_compiler.py` defines `AssignStmt.target: object` (singular). Any code importing from `ast_nodes.py` and accessing `.targets` will get `AttributeError`.
- **Fix:** Align `ast_nodes.py` with `mojo_compiler.py`: rename `targets` → `target`.

### BUG-018 — ForStmt: ast_nodes.py vs mojo_compiler.py field name mismatch
- **Severity:** high
- **Category:** attribute_mismatch
- **Location:** `ForStmt` definition
- **Description:** `ast_nodes.py` defines `ForStmt.targets: list` (plural), but `mojo_compiler.py` defines `ForStmt.target: object` (singular). Same hazard as BUG-017.
- **Fix:** Align `ast_nodes.py`: rename `targets` → `target: object`.

### BUG-019 — BinaryOp: ast_nodes.py vs mojo_compiler.py field order mismatch
- **Severity:** high
- **Category:** attribute_mismatch
- **Location:** `BinaryOp` definition
- **Description:** `ast_nodes.py` defines `BinaryOp` as `(left, op, right)` with `left` first. `mojo_compiler.py` defines it as `(op, left, right)` with `op` first. Positional construction would produce wrong results depending on which file is imported.
- **Fix:** Align `ast_nodes.py` to put `op` first to match `mojo_compiler.py`.

### BUG-029 — Nested FunctionDef without pre-pass info silently dropped
- **Severity:** medium
- **Category:** incomplete
- **Location:** `gimple_codegen.py` — `_gen_stmt_FunctionDef` inner closures
- **Description:** When a nested function definition is encountered but the pre-pass has not recorded it in `self._all_closures`, the codegen emits `/* TODO: closure '<name>' (no pre-pass info) */` and skips the function entirely. Any calls to it will fail.
- **Fix:** If a nested FunctionDef is not in `_all_closures`, perform on-the-fly closure lifting at the point of definition.

### BUG-032 — Variadic params detected by string prefix, not structured field
- **Severity:** medium
- **Category:** logic_error
- **Location:** `mojo_compiler.py` — `FunctionDef.params` field type
- **Description:** `FunctionDef.params` is a list of 2-tuples `(name, type|None)`. Variadic parameter detection uses `pn.startswith('*')` on the name string. This is fragile — a proper `Param` dataclass would make this explicit.
- **Fix:** Define a `Param` dataclass and convert to produce `Param` instances; update codegen to use `Param` fields.

## Medium

### BUG-009 — Comprehension fallthrough for non-collection iterables
- **Severity:** medium
- **Category:** stub
- **Location:** `gimple_codegen.py` — `_lower_comprehension`
- **Description:** Comprehension over `char *` and all non-`MojoList`/`MojoStr`/`MojoDict`/`MojoSet` types falls to `/* TODO: comprehension over <it_type> */`. Returns uninitialized result.
- **Fix:** Add `char *` branch (character iteration) and struct-iterator branch.

### BUG-010 — DispatchTable.emit_* stubs for unrecognized types
- **Severity:** medium
- **Category:** stub
- **Location:** `gimple_codegen.py` — `DispatchTable.emit_typedef`, `emit_table_init`, `emit_dispatch_call`
- **Description:** All three emit methods return `/* TODO: ... dispatch ... */` for `ARRAY_INDEX` type and any other unrecognized type, silently hiding unimplemented dispatch variants.
- **Fix:** Change else branches to `raise NotImplementedError` so unimplemented dispatch types are caught.

### BUG-014 — Comprehension dict key/value fields semantically reversed
- **Severity:** medium
- **Category:** logic_error
- **Node:** `Comprehension`
- **Location:** `mojo_compiler.py` definition; `gimple_codegen.py` lines ~6823-6824
- **Description:** `Comprehension.element` holds the key expr and `Comprehension.key` holds the value expr — backwards field naming. `ast_nodes.py` uses `value_expr` for the value. The codegen comments confirm the inversion: `# element = key`, `# key field holds the value`.
- **Fix:** Rename `Comprehension.key` → `value_expr` in `mojo_compiler.py`, update parser code, and update codegen to read `node.value_expr`.

### BUG-020 — StructDef: ast_nodes.py uses body/bases vs mojo_compiler.py fields/methods
- **Severity:** medium
- **Category:** attribute_mismatch
- **Location:** `StructDef` definition
- **Description:** `ast_nodes.py` defines `StructDef` with `bases: list` and `body: list`, while `mojo_compiler.py` defines it with `fields: list` and `methods: list`. Codegen accesses `.methods` and `.fields`.
- **Fix:** Align `ast_nodes.py` to use `fields` and `methods`.

### BUG-021 — WithItem: ast_nodes.py uses `name` vs mojo_compiler.py `alias`
- **Severity:** medium
- **Category:** attribute_mismatch
- **Location:** `WithItem` definition
- **Description:** `ast_nodes.py` defines `WithItem.name`, while `mojo_compiler.py` and the codegen use `item.alias`.
- **Fix:** Align `ast_nodes.py`: rename `name` → `alias`.

### BUG-022 — AssertStmt: ast_nodes.py uses `condition`/`message` vs codegen `value`/`msg`
- **Severity:** medium
- **Category:** attribute_mismatch
- **Location:** `AssertStmt` definition
- **Description:** `ast_nodes.py` defines `condition` and `message`. `mojo_compiler.py` and codegen use `value` and `msg`.
- **Fix:** Align `ast_nodes.py`: rename `condition` → `value`, `message` → `msg`.

### BUG-024 — TryStmt `finally` not emitted on normal-exit path
- **Severity:** medium
- **Category:** logic_error
- **Node:** `TryStmt`
- **Location:** `gimple_codegen.py` — `_gen_stmt_TryStmt`
- **Description:** `finally_body` is emitted only after the exception handler block and in the else block. It is NOT emitted at the end of the normal try-success path before `goto bb_after`. Python semantics require `finally` to run regardless of exception.
- **Fix:** After the normal try body, emit `finally_body` statements before the `goto bb_else/bb_after`.

### BUG-025 — For-loop fallthrough for non-collection types
- **Severity:** medium
- **Category:** incomplete
- **Location:** `gimple_codegen.py` — `_gen_for_iter`
- **Description:** For-loop over types other than `MojoList*`, `MojoStr*`, `MojoDict*`, `MojoSet*`, and user structs with `__has_next__`/`__next__` protocol emits `/* TODO: for loop over <it_type> */`. Iterating over `char *` also falls through.
- **Fix:** Add `char *` branch (byte character loop) and consider `int64_t` fallback.

### BUG-027 — Indirect function calls return stub zero
- **Severity:** medium
- **Category:** logic_error
- **Location:** `gimple_codegen.py` — indirect call lowering
- **Description:** Indirect calls via a variable return `0 /* TODO: indirect call via <name> */` instead of emitting the actual call. Return type is hardcoded to `'int'`.
- **Fix:** Load the function pointer, declare a temp of correct return type, emit `t = (*fnptr)(args);`.

### BUG-028 — isinstance() with tuple of types returns stub zero
- **Severity:** medium
- **Category:** stub
- **Location:** `gimple_codegen.py` — `isinstance()` lowering
- **Description:** `isinstance(x, (A, B))` emits `t = 0 /* TODO: isinstance with tuple of types */`. Silently returning 0 makes all isinstance-tuple conditions evaluate false.
- **Fix:** Expand into disjunction: `(isinstance(x, A) || isinstance(x, B))`.

### BUG-033 — TryStmt exception type not checked; all handlers run unconditionally
- **Severity:** medium
- **Category:** logic_error
- **Node:** `TryStmt`
- **Location:** `gimple_codegen.py` — `_gen_stmt_TryStmt`
- **Description:** The handler does not dispatch across multiple except clauses by exception type — every except clause runs unconditionally. No type-check is emitted.
- **Fix:** Emit a `mojo_exc_type_matches(handler_name_str)` type-check guard for each handler, with goto-chain logic between handlers.

### BUG-035 — Dict comprehension ignores multiple generators
- **Severity:** medium
- **Category:** incomplete
- **Location:** `gimple_codegen.py` — `_lower_comprehension` + dict comprehension
- **Description:** Multi-generator comprehensions (more than one `for` clause) only process `node.generators[0]`. Additional generators (nested for clauses with conditions) are silently ignored.
- **Fix:** Nest inner loop bodies inside outer loop, applying filter conditions before appending.

## Low

### BUG-015 — StringLiteral defined twice in mojo_compiler.py
- **Severity:** low
- **Category:** logic_error
- **Location:** `mojo_compiler.py` lines 123-126 and 141-145
- **Description:** `StringLiteral` is defined twice with `@dataclass`. Python silently replaces the first definition. Both are structurally identical, so no runtime bug today, but will cause confusion if they diverge.
- **Fix:** Remove the first `StringLiteral` definition.

### BUG-016 — CallExpr has duplicate @dataclass decorator
- **Severity:** low
- **Category:** logic_error
- **Location:** `mojo_compiler.py` line 157
- **Description:** `@dataclass` applied twice to `CallExpr`. Second application is a no-op but indicates a copy-paste error.
- **Fix:** Remove the duplicate `@dataclass` decorator.

### BUG-023 — Comprehension: ast_nodes.py value_expr vs mojo_compiler.py key field
- **Severity:** low
- **Category:** attribute_mismatch
- **Location:** `Comprehension` definition
- **Description:** `ast_nodes.py` defines `Comprehension.value_expr`; `mojo_compiler.py` uses `Comprehension.key` for the same slot. Codegen reads `node.key`. See also BUG-014.
- **Fix:** Align `ast_nodes.py`: rename `value_expr` → `key` (or fix both files per BUG-014).

### BUG-026 — Dead _COMMENT_* constants in gimple_codegen.py
- **Severity:** low
- **Category:** stub
- **Location:** `gimple_codegen.py` — `_COMMENT_*` constants
- **Description:** Several comment-string constants are defined but suppressed with `# Skip emitting comment`. The dead constants should be removed and the corresponding code paths audited.
- **Fix:** Remove the unused `_COMMENT_*` constants; verify code paths produce correct output or raise errors.

### BUG-030 — AugAssignStmt/MultiAssignStmt complex targets silently ignored
- **Severity:** low
- **Category:** incomplete
- **Location:** `gimple_codegen.py` — `AugAssignStmt` and `MultiAssignStmt` complex target handling
- **Description:** `AugAssignStmt` with a complex target (not `IdentExpr`, `MemberExpr`, or `SubscriptExpr`) is a no-op (`pass`). `MultiAssignStmt` with complex sub-targets is silently skipped. No warning or TODO comment is emitted.
- **Fix:** Emit `/* TODO: complex aug-assign/multi-assign target */` comment or raise a compiler error.

### BUG-031 — ast_nodes.py defines stale/phantom node types never produced by parser
- **Severity:** low
- **Category:** missing_handler
- **Location:** `ast_nodes.py`
- **Description:** `ast_nodes.py` defines several node types absent from `mojo_compiler.py`: `NoneLiteral`, `SelfExpr`, `PrintStmt`, `DeclareStmt`, `ListLiteral`, `DictLiteral`, `SetLiteral`, `TupleLiteral`, `Generator`, `Param`, `FieldDecl`. If any pass imports these from `ast_nodes.py` and passes them to `gimple_codegen.py`, they will hit the unknown-node fallthrough.
- **Fix:** Either delete `ast_nodes.py` or add a comment that `mojo_compiler.py` is the authoritative source.

### BUG-034 — ComptimeForStmt silently emits nothing for non-constant range
- **Severity:** low
- **Category:** logic_error
- **Node:** `ComptimeForStmt`
- **Location:** `gimple_codegen.py` — `_gen_stmt_ComptimeForStmt`
- **Description:** `_gen_stmt_ComptimeForStmt` only handles the case where the iterable is `range(...)` with all-constant arguments. For non-constant range or non-range iterables, it silently emits nothing (bare `pass`).
- **Fix:** Evaluate non-constant comptime for-loops at compile time if iterable is a constant list, or raise a compile-time error indicating the comptime loop could not be unrolled.
